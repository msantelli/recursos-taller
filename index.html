clase 01

Modelos locales

Correr un modelo «en tu computadora» significa que el programa que genera texto vive y trabaja en tu propia máquina, sin enviar nada a un servidor ajeno. Importa por tres razones: privacidad (lo que escribís no sale de tu escritorio), costo (no se paga por cada uso) e independencia (no dependés de que una empresa mantenga el servicio encendido).

Recursos

  • Ollama — para descargar y correr modelos locales desde la terminal.
  • LM Studio — aplicación con interfaz gráfica para probar modelos locales.
  • Hugging Face — la gran biblioteca de modelos abiertos.

clase 02

Agentes

Un agente es un modelo de lenguaje que además de responder puede usar herramientas: leer archivos, buscar información, ejecutar programas. Trabaja en ciclos de acción y evaluación — prueba algo, mira el resultado, corrige y sigue — como quien redacta, relee y vuelve a corregir.

Recursos

  • Claude Code — el agente con el que se construyó esta página.
  • Documentación de agentes de los principales proveedores: Anthropic · OpenAI · Google.

$ entorno

> Entorno de trabajo

Para experimentar por cuenta propia hacen falta dos cosas que no son IA: una terminal donde escribir órdenes y un Python ordenado donde instalar herramientas. Esta sección reúne los recursos para ambas.

Guía práctica: instalar Python y manejar un proyecto con uv
Paso a paso pensado para quien nunca instaló nada: instalar Python por primera vez, entender (y arreglar) la variable PATH, y llevar un proyecto de punta a punta con uv, con un ejemplo chico.

Manejo de entornos virtuales (Python)

Para que cada proyecto tenga sus propias dependencias sin romper la instalación del sistema. Basta con conocer una de estas opciones:

  • uv — gestor moderno y rápido de proyectos y entornos; uv sync instala todo lo declarado en el proyecto.
  • venv + pip — la vía estándar incluida con Python (python -m venv): guía de venv · guía oficial de instalación de paquetes en entornos virtuales.
  • conda / Miniconda — entornos que además manejan la versión de Python y librerías no-Python; común en ciencia de datos: conda · Miniconda.

Una misma terminal en los tres sistemas: bash y WSL

Linux y macOS ya traen una terminal tipo Unix (en macOS la shell por defecto es zsh, que a este nivel funciona igual que bash); en Windows se consigue instalando WSL, una Ubuntu que corre dentro de Windows. La ventaja de unificar: los mismos comandos —y los mismos tutoriales, scripts y herramientas del ecosistema— sirven en los tres sistemas. La desventaja: en Windows es una instalación extra (necesita reinicio y permisos de administrador) y al principio conviven dos mundos de archivos; para probar sin instalar nada, los agentes también corren en la web.

  • Instalar WSL — documentación oficial de Microsoft.
  • Configurar un entorno de desarrollo en WSL (Microsoft).
  • La línea de comandos para principiantes — tutorial oficial de Ubuntu (en inglés).
  • Manual de referencia de Bash (GNU).
  • VS Code dentro de WSL — documentación oficial.
  • Name That UI — página con glosario de elementos de interfaces gráficas para hacer pedidos más concretos a modelos de lenguaje.

glosario

Glosario

Los términos que circulan en el taller, definidos para gente de letras. El buscador filtra a medida que escribís.

agente
Un modelo de lenguaje que además de responder puede actuar: leer archivos, buscar, ejecutar programas, y evaluar el resultado antes de seguir. Trabaja en ciclos, como quien redacta, relee y corrige.
alucinación
Cuando el modelo afirma con total fluidez algo falso: una cita que no existe, un dato inventado. No es una mentira deliberada sino el costo de su oficio —producir texto plausible—. Por eso todo se verifica.
API
Una puerta de servicio para programas: en vez de una página para leer con los ojos, una dirección donde un programa le pide datos o servicios a otro. Los modelos de lenguaje pagos suelen usarse así.
arquitectura
La forma en que se reparten las piezas de un sistema y sus responsabilidades: qué hace el frontend, qué hace el backend, por dónde conversan. El plano del edificio, previo a los ladrillos.
backend
La parte que corre en el servidor, invisible para quien visita: bases de datos, cuentas de usuario, la lógica que no puede quedar en el navegador.
clave de API
La contraseña personal con que un servicio identifica quién le pide algo (y a quién cobrárselo). Se guarda en una variable de entorno y no se publica jamás.
código fuente
El texto que escriben las personas (o los modelos) para que la computadora haga algo. Es el manuscrito original de un programa: lo que se lee, se corrige y se versiona.
commit
Una instantánea guardada del repositorio en un momento dado, con un mensaje que dice qué cambió. Como fechar y firmar un borrador antes de seguir corrigiendo.
contexto
Todo lo que el modelo «tiene a la vista» en una conversación: la consigna, lo dicho antes, los documentos adjuntos. Es una memoria de trabajo limitada: lo que queda afuera, el modelo no lo sabe.
deploy
El acto de publicar: tomar el sitio que funciona en tu máquina y subirlo a un servidor para que cualquiera lo vea. El pasaje del manuscrito a la edición.
entorno
El conjunto de programas, versiones y configuraciones entre los que corre un proyecto: su ecosistema de trabajo. «En mi máquina funciona» casi siempre significa que dos entornos difieren; los entornos virtuales de Python existen para evitarlo.
frontend
La parte de un sitio que se ve y se toca: los textos, botones y estilos que corren en el navegador de quien lo visita.
harness
El andamiaje que rodea a un modelo para convertirlo en agente: las herramientas que puede usar, las reglas que sigue, los límites que no cruza. El modelo pone el lenguaje; el harness, el taller donde trabaja.
hosting
El servicio que hace de imprenta y distribución: los servidores donde vive un sitio publicado y desde donde se entrega a quien lo visita.
HTML
El lenguaje con que se marca la estructura de una página web: esto es un título, esto un párrafo, esto un enlace. Está más cerca de la anotación editorial que del cálculo.
IDE
Sigla de «entorno de desarrollo integrado»: el programa donde se escribe y organiza el código, con sus ayudas — resaltado, correcciones, terminal incorporada. El escritorio del editor, con todo a mano. VS Code es el más usado.
localhost
El nombre con que tu computadora se señala a sí misma. Un sitio en localhost existe solo para vos: es el borrador que todavía no salió de tu escritorio.
modelo de lenguaje
Un programa entrenado con cantidades enormes de texto que aprende a continuar una frase de manera plausible. Todo lo que hace —responder, traducir, resumir— deriva de ese oficio de completar texto.
modelo local
Un modelo que corre en tu propia computadora, sin enviar nada a un servidor ajeno. Se gana privacidad e independencia; a cambio, suelen ser modelos más chicos que los comerciales.
prompt
El texto que se le da al modelo como punto de partida: una consigna. Como toda consigna, su formulación condiciona la respuesta.
repositorio
Una carpeta cuya historia completa queda registrada: cada versión, con fecha, autor y una nota. El archivo de borradores de un proyecto.
sitio estático
Un sitio hecho de archivos fijos que el servidor entrega tal cual, como copias de un mismo original. No consulta bases de datos ni arma la página a medida de cada visitante. Esta página es un ejemplo.
temperatura
La perilla que regula cuánto se arriesga el modelo al elegir la palabra siguiente: baja, respuestas más previsibles; alta, más variadas y con más riesgo de disparate. La diferencia entre una traducción literal y una versión libre.
terminal
La interfaz donde la computadora se maneja escribiendo órdenes en vez de haciendo click: un diálogo por turnos — uno escribe, la máquina responde. Los agentes como Claude Code viven ahí.
token
La unidad mínima en que el modelo corta el texto: a veces una palabra entera, a veces un pedazo, como las sílabas de un verso escandido. Los límites y los precios de los modelos se miden en tokens.
variable de entorno
Un dato que un programa lee de su entorno en vez de llevarlo escrito adentro: típicamente claves y configuraciones. Permite publicar el código sin publicar los secretos.
vibecoding
Programar delegando la escritura del código a un modelo de lenguaje. La destreza central no es tipear: es especificar bien lo que se quiere, criticar el resultado e iterar.

Términos fronterizos

Sugeridos por el público del taller: bordean el tema más que pertenecerle. Pero la frontera es zona fértil.

cognición
Los procesos de conocer: percibir, recordar, razonar, aprender. Si lo que hacen los modelos de lenguaje merece ese nombre es una discusión abierta — de las buenas, porque obliga a definir qué entendemos por comprender un texto.
entropía
Medida de la incertidumbre sobre lo que viene: cuanto más impredecible la próxima palabra, más entropía. Un verso de tango consagrado tiene poca; el arranque de un poema de vanguardia, mucha. Los modelos trabajan prediciendo en medio de esa incertidumbre (ver temperatura).

Ningún término coincide con la búsqueda. Se pueden sugerir términos nuevos en clase.

$ seguridad

> Seguridad mínima

Cinco puntos para experimentar con tranquilidad. Nada de esto es para asustarse: es el equivalente digital de cerrar la puerta al salir.

  • Local no es público. Abrir una página en tu propia máquina (doble click en el archivo, o localhost) es un borrador que solo ves vos. Publicarla es otra cosa: lo público lo ve cualquiera, y puede quedar cacheado —guardado en copias ajenas— aunque después lo borres.
  • El código se publica; las claves no. Una clave de API es la contraseña con que un servicio pago te identifica (y te cobra). Va en una variable de entorno: un archivo .env que queda fuera del repositorio (listado en .gitignore). En el hosting, las claves se cargan aparte, en su configuración.
  • Git no olvida. Una clave commiteada queda en la historia del repositorio aunque la borres en la versión siguiente. Si pasa, la clave se revoca y se genera una nueva; borrarla del último commit no alcanza.
  • Los prompts también son texto que viaja. No pegues claves ni datos personales —propios o ajenos— en prompts ni en repositorios públicos.
  • Por qué esta página es segura de publicar: es estática y no usa claves. Un proyecto con backend o APIs pagas convierte todo lo anterior en la primera preocupación, no en la última.
